## 二、维度估算规则

### 2.1 ES（环境生存能力）

**定义**：能量代谢效率，系统在环境中持续运作的能力

**公式**：
```
ES = 基础分(30) + Channels贡献 + 存储贡献 + 守护进程贡献
```

**详细规则**：

| 指标 | 贡献 | 说明 |
|------|------|------|
| 基础分 | +30 | 能运行即可获得 |
| Channels数量 | +5/个 | 最多5个渠道=25分 |
| 持久化存储 | +10 | `storage`/`db`/`database` 配置存在 |
| 守护进程 | +10 | `cron`/`heartbeat`/`health_check` 配置存在 |

**上限**：90

**示例**：
- 仅有Web界面：ES = 30 + 5 = 35
- Web + API + Slack + 持久化：ES = 30 + 15 + 10 = 55
- 全功能 + 守护进程：ES = 30 + 15 + 10 + 10 = 65

---

### 2.2 IS（信息处理能力）

**定义**：感知带宽与信噪比，系统获取和处理信息的能力

**公式**：
```
IS = 基础分(20) + Memory贡献 + RAG贡献 + 多模态贡献 + 分析贡献
```

**详细规则**：

| 指标 | 贡献 | 说明 |
|------|------|------|
| 基础分 | +20 | 最基本的信息处理 |
| Memory系统 | +15 | `memory`/`context` 配置或目录存在 |
| RAG/知识库 | +15 | `rag`/`knowledge`/`vector_db` 配置存在 |
| 多模态Skills | +3/个 | 最多5个=15分，识别关键词：vision, image, 视觉, 多模态, ocr, visual |
| 日志分析 | +10 | Skills目录中有分析类Skill |

**上限**：90

**示例**：
- 基础LLM问答：IS = 20
- + 记忆系统：IS = 20 + 15 = 35
- + RAG：IS = 20 + 15 + 15 = 50
- + 视觉Skill：IS = 20 + 15 + 15 + 3 = 53

---

### 2.3 MS（模型构建能力）

**定义**：内部预测模型的压缩比、精度及递归深度

**公式**：
```
MS = 模型基准 + Skills贡献 + 工作流贡献
```

**详细规则**：

#### 模型基准分

| 模型系列 | 典型模型 | 基准分 |
|---------|---------|--------|
| GPT-4系列 | gpt-4o, gpt-4-turbo, gpt-4 | 60-75 |
| GPT-3.5 | gpt-3.5-turbo | 55 |
| Claude-3.5 | claude-3-5-sonnet | 78 |
| Claude-3 | claude-3-opus, claude-3-sonnet | 72-76 |
| Claude-3-haiku | claude-3-haiku | 60 |
| Llama-3 | llama-3-70b, llama-3-8b | 58-68 |
| Llama-2 | llama-2-70b, llama-2-7b | 52-62 |
| Qwen | qwen-72b, qwen-14b, qwen-7b | 52-65 |
| DeepSeek | deepseek-67b, deepseek-33b | 55-66 |
| GLM | glm-4, glm-4v, glm-3 | 58-70 |
| 本地模型 | local, ollama, vllm | 40-45 |
| 未知模型 | - | 50 |

#### Skills贡献

| 指标 | 贡献 | 说明 |
|------|------|------|
| Skills数量 | +2/个 | 最多10个Skills=20分 |

#### 工作流Skills

| 指标 | 贡献 | 说明 |
|------|------|------|
| 工作流Skills | +10 | 识别关键词：workflow, 工作流, pipeline, chain, agent, orchestrat |

**上限**：90

---

### 2.4 VS（价值对齐能力）

**定义**：进化方向的约束边界清晰度

**公式**：
```
VS = 基础分(40) + 安全配置贡献 + 内容过滤贡献 + 用户反馈贡献 - 漏洞惩罚
```

**详细规则**：

| 指标 | 贡献 | 说明 |
|------|------|------|
| 基础分 | +40 | 最低安全保障 |
| allowlist | +8 | `allowlist`/`whitelist` 配置存在 |
| 审计日志 | +7 | `audit`/`logging` 配置存在 |
| 内容过滤 | +10 | `filter`/`content_filter` 配置存在 |
| 用户反馈 | +10 | `feedback`/`user_feedback` 配置存在 |
| 漏洞 | -10/个 | 每次检测到的安全问题 |

**上限**：95

**安全配置优先级**：
1. allowlist > blacklist（白名单优于黑名单）
2. 审计日志 > 无日志
3. 内容过滤 > 无过滤
4. 用户反馈机制增强可追溯性

---

### 2.5 CE（持续进化能力）

**定义**：变异-选择-遗传循环的效率

**公式**：
```
CE = 基础分(20) + Skills贡献 + 定时任务贡献 + 自我改进贡献 + 轨迹记录贡献
```

**详细规则**：

| 指标 | 贡献 | 说明 |
|------|------|------|
| 基础分 | +20 | 基本的代码部署能力 |
| Skills数量 | +2/个 | 最多10个=20分 |
| Cron/Heartbeat | +15 | `cron`/`heartbeat`/`scheduled_tasks` 配置存在 |
| 自我改进Skills | +10/个 | 最多2个=20分，识别关键词：self_improve, 自我, learn, evolution, improve |
| 轨迹记录 | +10 | `trajectory`/`save_trajectories` 配置存在 |

**上限**：90

**自我改进识别逻辑**：
```python
self_improve_keywords = ["self_improve", "self-improve", "自我", "learn", "学习", "evolution", "进化", "improve"]
# 任一关键词出现在skill名称或内容中即算作自我改进Skill
```

## 三、Skill类型自动识别

### 3.1 识别关键词表

| 类型 | 关键词 |
|------|--------|
| 多模态 | vision, image, 视觉, 多模态, ocr, visual, generate_image |
| RAG | rag, knowledge, 知识库, 检索, retrieval, vector, embedding, 文档, search |
| 工具 | tool, api, function, 工具, 调用, browser, web, http |
| 记忆 | memory, 记忆, state, 状态, persist, storage, db, database |
| 安全 | safety, 安全, filter, 审计, permission, 权限 |
| 自我改进 | self_improve, 自我, learn, 学习, evolution, 进化, improve |
| 工作流 | workflow, 工作流, pipeline, chain, agent, orchestrat |
| 分析 | analysis, 分析, log, 日志, analytics, 统计, monitor, 监控 |

### 3.2 识别算法

```python
def detect_skill_type(skill_name: str, skill_content: str = "") -> List[str]:
    """
    检测Skill类型
    
    1. 合并skill名称和内容
    2. 对每个类型遍历关键词
    3. 匹配到任一关键词则标记该类型
    4. 返回所有匹配的类型列表
    """
    content = (skill_name + " " + skill_content).lower()
    detected = []
    
    for skill_type, keywords in SKILL_TYPES.items():
        for keyword in keywords:
            if keyword in content:
                detected.append(skill_type)
                break
    
    return detected
```

## 四、数据来源优先级

### 4.1 配置字段优先级

当同一信息有多个可能字段时，按以下优先级读取：

| 信息类型 | 优先级顺序 |
|---------|-----------|
| Channels | `channels` > `channel` > 从skills推断 |
| 模型 | `model` > `runtime.model` > `llm.model` |
| 存储 | `storage` > `db` > `database` |
| 记忆 | `memory` > `context` > memory/目录存在 |
| RAG | `rag` > `knowledge` > `vector_db` |

### 4.2 平台检测优先级

1. OpenClaw（`~/.openclaw/openclaw.json`）
2. Hermes（`~/.hermes/config.json`）

检测到第一个可用平台即停止。

## 五、置信度评估

### 5.1 数据完整度评分

| 评分 | 条件 |
|------|------|
| 高置信度 [CL-H] | 模型明确 + Skills ≥ 3 + 至少2个维度有明确数据 |
| 中置信度 [CL-M] | 模型明确 或 Skills ≥ 3 |
| 低置信度 [CL-L] | 仅有配置文件，无Skills扫描结果 |

### 5.2 降级策略

当自动检测失败时，自动降级到手动评估模式：

```
自动检测失败 → 检查配置文件 → 扫描Skills目录 → 降级为手动描述评估
```
