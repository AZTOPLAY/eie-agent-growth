## 🐛 P0-1：零基评分法声明与代码不一致

### 问题描述
**位置**: `dimension_estimator.py` 181-189 行

SKILL.md 声称：
> v3.2 重大改进：零基评分法（无基础分，全部靠实际能力挣分）

但实际代码中仍然存在"基础分10分"：
```python
if self.data.persistent_storage:
    # 基础分10分，实际使用再加10分  ← 矛盾！
    storage_score = 10
```

### 影响分析
- **严重性**: 🔴 严重
- **影响**: 声称零基评分，但实际仍有基础分
- **结果**: "僵尸 Agent"（配置存在但未使用）仍然能得基础分

### 修复方案
```python
# 【v3.3 修复】真正零基评分：无基础分，完全靠实际使用挣分
if self.data.persistent_storage:
    if self.quality and self.quality.memory_usage_rate > 0:
        # 实际使用率 × 满分
        storage_score = int(self.quality.memory_usage_rate * 20)
        source["storage"] = f"实际使用率{self.quality.memory_usage_rate*100:.0f}% (+{storage_score})"
    else:
        # 配置存在但未使用 = 0 分
        storage_score = 0
        source["storage"] = "配置存在但未使用 (0)"
```

### 测试验证
```
测试场景：持久化存储配置存在但未使用

v3.2结果：
  配置持久化 (+10) → 基础分10分

v3.3结果：
  配置存在但未使用 (0) → 0分

✅ 修复成功：真正零基评分
```

## 🐛 P0-2：IS 维度评分逻辑错误 - 指数级降低得分

### 问题描述
**位置**: `dimension_estimator.py` 196-202 行

使用乘积计算质量系数，导致得分指数级降低：

```python
# 得分 = 记忆使用率 × 内容质量 × 40
memory_quality = self.quality.memory_usage_rate * self.quality.memory_content_quality
memory_score = int(memory_quality * 40)
```

### 影响分析
- **严重性**: 🔴 严重
- **影响**: 即使指标不错，得分也会被大幅降低
- **示例**：
  - 使用率 = 50% (0.5)
  - 内容质量 = 80% (0.8)
  - 乘积 = 0.4
  - 得分 = 40%（本应接近60-70%）

### 修复方案
```python
# 【v3.3 修复】改用加权平均而非乘积（避免指数级降低得分）
# 得分 = (使用率×0.6 + 内容质量×0.4) × 40
memory_quality = (self.quality.memory_usage_rate * 0.6 +
                  self.quality.memory_content_quality * 0.4)
memory_score = int(memory_quality * 40)
```

### 测试验证
```
测试场景：使用率50%，内容质量80%

v3.2（乘积逻辑）：
  质量系数 = 0.5 × 0.8 = 0.4
  得分 = 0.4 × 40 = 16分

v3.3（加权平均）：
  质量系数 = 0.5×0.6 + 0.8×0.4 = 0.62
  得分 = 0.62 × 40 = 25分

✅ 修复成功：得分提升56.25%（更合理）
```

## 🐛 P0-3：VS 维度漏洞惩罚过于严厉

### 问题描述
**位置**: `dimension_estimator.py` 246-251 行

所有漏洞统一惩罚 15 分，不考虑严重程度：

```python
vuln_penalty = len(self.data.vulnerabilities) * 15
```

### 影响分析
- **严重性**: 🔴 严重
- **影响**：
  - 1个P2漏洞 = -15分（降低25%）
  - 2个P2漏洞 = -30分（降低50%）
  - 3个P2漏洞 = -45分（降低75%）
- **问题**：P0和P2漏洞惩罚相同，不合理

### 修复方案
```python
# 【v3.3 修复】漏洞惩罚分级（P0-15分，P1-8分，P2-3分）
def _calculate_vulnerability_penalty(self, vulnerabilities):
    total_penalty = 0
    for vuln in vulnerabilities:
        severity = vuln.get("severity", "P2").upper()
        if severity == "P0":
            total_penalty += 15
        elif severity == "P1":
            total_penalty += 8
        else:  # P2
            total_penalty += 3
    return total_penalty
```

### 测试验证
```
测试场景：不同严重程度的漏洞

v3.2（固定惩罚）：
  1个漏洞 = -15分

v3.3（分级惩罚）：
  1个P0漏洞 = -15分
  1个P1漏洞 = -8分
  1个P2漏洞 = -3分
  1个P0+1个P1+1个P2 = -26分

✅ 修复成功：分级惩罚更合理
```

## 🐛 P0-4：质量调整系数过于严厉

### 问题描述
**位置**: `quality_estimator.py` 145-154 行

新系统未使用时，质量系数导致 70% 的惩罚：

```python
if quality.memory_usage_rate > 0:
    adjusted["IS"] = int(base_scores["IS"] * (0.5 + 0.5 * is_quality_factor))
else:
    adjusted["IS"] = int(base_scores["IS"] * 0.3)  # 无使用则大幅降分
```

### 影响分析
- **严重性**: 🔴 严重
- **影响**：
  - 新系统刚配置好，还没来得及使用就被大幅降分
  - base_score = 50 → adjusted = 15（**降低70%**）
- **问题**：没有"冷启动期"保护

### 修复方案
```python
# 【v3.3 修复】降低调整系数：从0.3改为0.5，增加7天保护期
def calculate_quality_adjusted_scores(base_scores, quality, config_mtime=0):
    # 判断是否在保护期内（7天）
    if config_mtime > 0:
        days_since_config = (datetime.now().timestamp() - config_mtime) / 86400
    in_protection_period = days_since_config < 7

    if quality.memory_usage_rate > 0:
        adjusted["IS"] = int(base_scores["IS"] * (0.5 + 0.5 * is_quality_factor))
    else:
        # 保护期内只降50%，保护期外也降50%（原70%）
        adjusted["IS"] = int(base_scores["IS"] * 0.5)
```

### 测试验证
```
测试场景：新系统未使用（base_score=50）

v3.2（无保护期）：
  50 × 0.3 = 15分（降70%）

v3.3（保护期/保护期外）：
  50 × 0.5 = 25分（降50%）

✅ 修复成功：惩罚降低50%，更温和
```

## 🛠️ P2-1：统一降级方案

### 问题描述
**位置**: `dimension_estimator.py` 221-228 行

降级方案仍然有基础分，与"零基评分"矛盾：
```python
if self.data.memory_system:
    score += 20  # ← 基础分
    source["memory"] = "记忆系统配置 (+20)"
```

### 修复方案
```python
# 【v3.3 修复】降级方案也零基：只给实际使用的项目分
if self.data.workspace_path:
    memory_dir = Path(self.data.workspace_path) / "memory"
    if memory_dir.exists():
        # 检查是否有实际内容
        has_content = False
        for md_file in memory_dir.glob("*.md"):
            try:
                if md_file.stat().st_size > 100:  # 至少100字节
                    has_content = True
                    break
            except:
                pass

        if has_content:
            score += 20
            source["memory"] = "记忆系统有内容 (+20)"
        else:
            source["memory"] = "记忆系统存在但无内容 (0)"
```
